# ASR Studio v2 · Audit trước khi sửa

Baseline `53c0f39878bcf175e65160cf255a579c5e80908a` từ `main` tại thời điểm audit. PR #250 nằm trên `feat/portfolio-type-system`; các thay đổi của nó không nằm trong baseline. Handoff v2 nằm trong checkout người dùng và đang bị Git ignore. Giữ ảnh gốc có thông tin deployment và account trong máy, dùng dữ liệu mẫu cho ảnh demo công khai.

## Kiến trúc và ranh giới

- Web HTML/CSS và ES modules nguyên bản trong `src/asr_studio/web/`, phục vụ từ FastAPI trong cùng repo. `routes.py` phục vụ `/access`, `/` và `/meetings/{id}`. Lịch, sidebar, trình phát và tab cuộc họp ở shell chung. Settings, New Meeting và xác nhận xóa dùng dialog.
- `app.py`, `auth.py`, `config.py` bảo vệ web theo host/origin cấu hình và cookie ký, HttpOnly, SameSite Strict, Secure theo HTTPS hoặc cấu hình. Access token và khóa ký lưu phía server. Provider OAuth là phiên kết nối riêng. Extension dùng quyền extension origin và credential theo device/session.
- `recordings.py`, `media.py`, `storage.py` quản lý SQLite, staging và media theo `ASR_DATA_DIR`. Upload qua create → chunks → complete → create meeting. Extension lưu audio cục bộ bằng IndexedDB, server lưu chunks rồi archive và derivative qua hàng đợi. ASR và Notes dùng task/worker, Notes chạy trong service riêng. Pipeline lưu workflow, step, attempt và snapshot trong SQLite. ASR installer có hàng đợi file và heartbeat riêng.
- `compose.yaml` giữ các volume data, auth, provider và model-install. App/worker nhìn `ASR_MODEL_HOST_PATH` dưới `/models:ro`. Installer có `/models:rw`, volume hàng đợi, và egress. Worker chạy network nội bộ. Community-1 dùng model path đã chuẩn bị trong mount. Giữ các ranh giới này ở PR UI.

## Kế hoạch thay đổi và rollback

1. **Layout/markup**. Sidebar, Full Calendar, footer/About, responsive và light/dark. Giữ form, state và đường dẫn. Rollback bằng revert PR. Giữ bố cục footer theo ảnh người dùng, hai icon cân giữa và version từ build ở dòng dưới.
2. **Frontend state trên API hiện có**. Settings popup/providers, ASR manager, Devices/Chrome Extension, New Meeting, editor Notes/Transcript. Các PR nhỏ verify riêng, giữ focus/status sau lỗi lẫn success. Rollback bundle và markup cùng nhau. Không clear browser state hoặc credential để rollback.
3. **API bổ sung có điều kiện**. Auto Processing defaults, Notes run override, Transcript diarization override, catalog/installer cho diarization và fresh install. Đề xuất field opt-in, giữ request/record cũ đọc được và chạy cùng defaults cũ. Nếu cần migration, dùng bản sao disposable để thử nâng cấp và phục hồi, giữ snapshot và không đổi model folder. Scope có delete/credential/volume phải có thiết kế và phê duyệt trước.
4. **Thử liên hoàn**. Dùng fake provider từ bộ test, local audio tạo test và thiết bị test mới. Ghi trạng thái ACK và kết quả thật tại từng mốc. Ghi riêng kiểm thử deployment ngoài máy nếu có môi trường được phép.

## Khác biệt với prototype

- Settings sản phẩm tiếp tục dùng modal. Prototype là workspace navigation. Các form riêng và semantics đăng nhập giữ theo provider.
- Install ASR có backend thật. Readiness thuộc worker và host; screenshot bốn model ready chỉ là một deployment. Fresh preset và nút gỡ trong prototype chưa phản ánh contract hiện hành.
- Code mẫu, callback mẫu, simulated extensions, giả lập progress và badge connected không đi vào production. OMP chỉ cấp authorization URL/input; không invent activation URL. Google usage không có nguồn xác minh.
- Upload dùng policy runtime, title trim, API chunk thực và create acknowledgement. Extension capture được giữ trong extension.
- Notes rich editor/email, run-specific preferences, diarization selection cần các bước độc lập. Giữ Markdown cũ, citations và mọi bản trước rerun.
- Footer dùng ảnh gốc làm tham chiếu cho hàng icon và version. About và provider shortcuts tiếp tục có dữ liệu runtime.

## Tài liệu tham chiếu

Audit dùng hai tài liệu `docs/ASR_STUDIO_UX_GUIDE.md` và `docs/ACCEPTANCE_CHECKLIST.md` trong handoff ASR Studio v2. Các ảnh gốc dùng để đối chiếu vị trí và hành vi. Trình duyệt loopback chạy `prototype/index.html` ở desktop và mobile để kiểm tra các tương tác mẫu của Notes, Transcript, Calendar, New Meeting, Settings, callback và pairing. Các khả năng trong bảng đến từ source của baseline. Ảnh demo triển khai dùng dữ liệu mẫu.
